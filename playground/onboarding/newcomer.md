# 新人入门

欢迎加入青禾实验室。这份文档帮你在第一周把 QHP 相关的东西串起来。内容比较长，建议第一天通读一遍，之后当目录用。

## 先了解你会接触到的东西

实验室里和 QHP 相关的东西主要有四块：

1. **协议本身**：QHP 是实验室内部的会话层协议，负责把双方从"互相认识"推进到"可以传业务数据"。协议的规则写在 `notes/` 目录里。
2. **qhpd**：QHP 的服务进程，跑在每台上游节点上。部署、配置、日志这些运维相关的内容在 `ops/` 目录里。
3. **网关**：实验室内网入口的 `qhp-gw`，客户端一般先连网关，再由网关转发给某台 qhpd。网关的文档在 `gateway/` 目录里。
4. **SDK**：写客户端时用的库，有 Python 和 TypeScript 两个版本，文档在 `sdk/` 目录里。

另外还有几个目录你会经常用到：

- `meetings/`：协议组和网关组的会议纪要。很多"为什么是这个值"的问题，答案都在纪要里
- `rfc/`：改进提案。提案不等于已经实施，每篇开头都写了状态
- `archive/`：旧文档。里面的数值大多已经过时，只在考古时看

## 第一天：读协议

按这个顺序读，一个上午就能读完：

1. `notes/overview.md`：协议是干什么的，会话建立有哪几步
2. `notes/probe.md`、`notes/handshake.md`、`notes/ticket.md`、`notes/lock.md`：会话建立的四步，一步一篇
3. `notes/timeout.md`：超时和重试
4. `notes/frames.md`：帧类型、心跳
5. `notes/errors.md`：错误码。不用背，知道百位数代表哪一步就行
6. `notes/glossary.md`：术语表。实验室里有不少内部叫法，比如"泊位""回连""摘除"，听不懂先查这里

读的时候建议自己画一张图：发起方和对端之间，四步分别发了什么报文、对方回了什么、什么情况下失败。画完这张图，后面看日志和排查问题都会轻松很多。

## 第二天：读网关和运维

1. `gateway/overview.md`：网关做什么、不做什么
2. `gateway/berth.md` 和 `gateway/upstream.md`：网关最常出问题的两块
3. `ops/deploy.md`：qhpd 怎么部署，配置文件在哪
4. `ops/logs.md`：日志在哪，怎么调日志级别
5. `ops/qhpctl.md`：命令行工具。不用全记住，知道有哪些子命令就行
6. `ops/alerts.md` 和 `ops/oncall.md`：告警和值班。入职一个月后会排进值班表，提前熟悉

## 第三天：动手

1. 按 `onboarding/lab-env.md` 的说明，找导师开通测试环境的权限
2. 装 Python SDK，用 `sdk/python.md` 里的最小示例连一次预发网关，看到会话锁定成功就算通过
3. 在测试节点上执行 `qhpctl sessions list`，找到你自己刚才建立的会话
4. 用 `qhpctl trace --session <你的会话 ID>` 看一下四步各花了多少时间

做第 2 步时如果连不上，先别急着问人，按下面的顺序自己查一遍：

- 地址和端口对不对：连网关用网关的端口，直连 qhpd 用 qhpd 的端口
- 票证放对地方没有：票证要放在票夹里，测试票证从共享目录拷
- 报了什么错误码：对照 `notes/errors.md` 和 `gateway/errors.md` 看是哪一步

## 第四、五天：读排查手册

`ops/runbook-handshake.md` 是握手失败的排查手册，写得比较完整，值得细读。读完以后，找导师要一个以前的真实案例，自己按手册走一遍。

读手册的时候注意一个思路：先确认范围，再按错误码分支，最后才去翻详细日志。不要一上来就把日志级别调到 `debug` 然后在几十万行日志里找。

## 导师和周报

每个新人入职时会分配一位导师，第一个月的问题优先问导师。导师不是你的上级，只负责帮你尽快熟悉环境，有什么不懂的随时问，不用不好意思。

每周五下班前交一份周报，发给导师和组长，格式很简单：

1. 本周做了什么：每件事一两句话，写清楚结果，不要只写"学习了 xx"
2. 遇到了什么问题：卡住的地方、还没想明白的地方
3. 下周打算做什么

周报的作用是让导师知道你卡在哪，好及时帮你，不是考核。写得越具体，导师越容易帮上忙。第一个月的周报里，建议专门写一段"这周搞懂了什么"，用自己的话复述一遍，导师会帮你看理解得对不对。

## 常用命令速查

第一周你会反复用到下面这几个命令，详细用法看 `ops/qhpctl.md`：

| 想做什么 | 命令 |
|----------|------|
| 看 qhpd 是不是在跑 | `qhpctl status` |
| 看当前有哪些会话 | `qhpctl sessions list` |
| 看会话建立每一步花了多久 | `qhpctl trace --session <会话 ID>` |
| 看网关和上游的状态 | `qhpctl gw status` |
| 改完配置先检查一遍 | `qhpctl check-config <配置文件>` |
| 看各个组件的版本 | `qhpctl version` |

注意 `qhpctl` 只能在 qhpd 或网关所在的机器上执行，在自己的电脑上是用不了的。

## 写文档的规范

实验室的文档都放在这个资料目录里，你以后也会写。写之前了解几条约定：

- 一篇文档只讲一件事，标题就说清楚是哪件事
- 数值写清楚单位：毫秒还是秒、KB 还是字节
- 引用别的文档时写相对路径，比如 `notes/timeout.md`
- 改了数值，要同步检查其他引用这个数值的文档；改不完的，在文档里注明"以某某文档为准"
- 过时的文档不要直接删，挪到 `archive/` 并在开头标【已过时】
- 会议上定下来的事情，以会议纪要为准，纪要要写明结论和理由

## 第一个月的目标

第一个月结束时，导师会和你一起对照下面几条看看进度：

1. 能不看文档讲清楚会话建立的四步，以及每一步失败时报什么错误码
2. 能用 SDK 写一个小程序，完成一次会话建立、发几条消息、正常拆除
3. 能独立按排查手册处理一次握手失败
4. 知道网关的泊位、回连、摘除分别是什么
5. 在测试环境跟着值班的同事看过至少一次真实告警的处理过程

做到这几条，就可以排进值班表了。

## 实验室的几条规矩

- **线上机器不要随便改**：测试请用测试环境。线上 qhpd 的配置只能通过配置发布修改，不要登录上去手改
- **危险命令先问人**：`qhpctl purge`、重启网关、`qhpctl gw drain` 这类会影响大量会话的命令，执行前必须得到值班负责人同意，哪怕是在你觉得"肯定没问题"的时候
- **改了东西要留记录**：改了测试环境的配置，在群里说一声，免得别人排查半天发现是你改的
- **不确定的数值去查文档**：别凭记忆说数字。QHP 里相似的时间参数很多，探活间隔、默认超时、心跳间隔、泊位回收时间，记混是常事
- **文档有错就改**：发现文档和实际行为不一致，先在群里确认，再直接改文档，不要只是自己知道

## 遇到看不懂的东西

刚开始一定会遇到很多看不懂的词和数字，这很正常。建议这样处理：

1. 先查 `notes/glossary.md`，内部叫法基本都在里面
2. 再用关键词在资料目录里搜一下，很多问题在会议纪要里有来龙去脉
3. 还是不懂，记下来，攒几个一起问导师

不要因为怕问"太简单的问题"而自己猜，猜错的代价比问一句大得多。

## 怎么提问

实验室的人都很乐意回答问题，但请按下面的方式提问，能省很多来回：

1. 说清楚你在做什么：连的是哪个环境、哪台机器、经不经过网关
2. 贴错误码，不要只说"连不上"
3. 贴相关的几行日志，不要整个文件发过来
4. 说你已经试过什么

协议相关的问题在协议组的群里问，网关相关的在网关组的群里问，告警相关的在告警群里问。

## 常见误区

下面这些是新人最常踩的坑，每一条都有人踩过不止一次。

**1. 把探活间隔当成超时**

探活间隔是 80 毫秒，这是发 `QHP-PING` 的节奏，不是超时。默认超时是 2700 毫秒，看 `notes/timeout.md`。这是新人最常犯的错误，几乎每一届都有人在周报里写"超时 80 毫秒"。

**2. 把心跳间隔当成超时**

心跳间隔是会话锁定以后才用的，和会话建立时等待应答的超时没有关系。

**3. 把网关端口和 qhpd 端口搞混**

连网关是 4722，直连 qhpd 是 4721。端口填错的表现是一直连不上，或者连上了但不是你想连的那个。

**4. 以为准入名单是空的就是不限制**

正好相反，名单为空会拒绝所有地址。

**5. 改了环境变量以为马上生效**

环境变量只在进程启动时读一次，改完要重启 qhpd。准入名单和网关配置不一样，它们可以用 `qhpctl reload`、`qhpctl gw reload` 热加载。

**6. 把 RFC 当成已经实施的功能**

`rfc/` 里的提案有草案、已接受、已否决几种状态。已接受也不代表已经发布，要看当前版本号。

**7. 引用 archive 里的数值**

`archive/` 里的旧文档数值大多已经过时，回答问题、写文档时不要引用。
